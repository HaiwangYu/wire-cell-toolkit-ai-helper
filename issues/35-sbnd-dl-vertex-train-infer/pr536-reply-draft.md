Thanks for the careful read. All ten points were correct; the fixes are in `21562551` (the knob-off output is still identical to master on MC-10 and NCpi0-19, every branch and every Bee layer; doctests clus 473/473, root 10/10; configs byte-identical).

1. **Union mode** — the payload is now recorded right after this call's own inference, before the OFF voxels are pooled; `n_off_voxels` says how many were appended afterwards. A standalone replay reproduces the recorded payload in every mode.
2. **voxels / union OFF call** — `dual_chain_scn_voxels` now records too, as `pass = 2` (`off-voxels`): exact cloud and payload, no decision fields (that call's decision is production's). So "every network call" holds in all three modes.
3. **Network throws** — `status` column: 0 ok, 1 the network threw (cloud recorded, payload empty), 2 unexpected payload size. The replay skips them.
4. **Truth per candidate** — kept the scalar max-edep `truth_*` (now `truth_valid` only when it deposited energy) and added every interaction of the event as vectors: `truth_n`, `truth_all_{nu_idx, pdg, ccnc, E, edep, t, x, y, z, reco_x, reco_y, reco_z}`. The reader picks the interaction per candidate (we use "its shifted vertex lies inside the candidate's cloud"); in the 1006-event sample 6 of 474 events have two candidates.
5. **Pre-snap pick** — `rerank_valid`, `rerank_x/y/z`, `rerank_row`: the call's own choice (legacy snap or rerank winner) before the dual-chain snap.
6. **transferred but not accepted** — real state (a snap transfer then the two-end-break veto; 9 of 480 rows in the sample). `two_end_veto` column added and the combination documented in the header.
7. **Truth frame** — measured on the 373 selected candidates of the 1006-event MC sample: the nearest cloud point is 0.42 cm (median) from the SCE-shifted truth vs 0.69 cm from the raw truth, 93 % vs 69 % within 1 cm; the x offset between the two frames is 0.06 cm median. The neutrino-time vs flash-time term is sub-mm for beam neutrinos, so it is not applied.
8. **Row indices** — `trad_row`, `rerank_row`, `dl_row`: position inside the cloud's vertex block, -1 if the vertex is not a cloud row. They identify the vertex even when `dl_vtx_cloud_no_exclusion` restored the coordinates.
9. **`tcn_overrides`** — now merged last, after the named keys; `pr_knobs={cosmic_consistent_fv: false}` compiles to false. Default `{}`, all configs byte-identical.
10. **`pr_knobs={dl_vtx_dump: true}`** — `truth_sce_applied` column says whether an `sce_field` was configured; the writer also gets its own `dl_vtx_dump` key from the same gate, and the `pr()` comment says the TLA is the way to turn the dump on.

Smaller points: a `dl_vtx_dump` default-false check in both knob-default doctests and a small doctest on the `DlVtxCall` contract (a writer test with a full Ensemble does not fit the root test file); with the writer key the two trees are written on every event (empty when nothing was recorded), so the schema no longer varies; `T_dlvtx_cloud` keeps one row per point (0.17 MB/event, and `TTree::Draw` on the points is what we use) and gains a `pass` column; the flow doc's sections 2 and 4 are current.

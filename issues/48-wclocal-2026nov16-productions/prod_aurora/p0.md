### Build note: the release `-Werror` flags

0.38.0 is a numbered release, so `wscript` `is_development()` is False. `waft/wcb.py:170` then adds `-Werror -Wall -pedantic` to `CXXFLAGS`. Our earlier Aurora builds were development versions and never had these flags.

**Libraries and executables:** with UPS gcc 12.1 (e26), every one compiles cleanly under them.

**Two doctest programs do not compile:**
- `clus/test/doctest_dv2_space.cxx:35`: `for (const std::string rep : {...})`, error `-Werror=range-loop-construct` (the fix is `const std::string& rep`);
- `pytorch/test/doctest_fm_direct.cxx`: doctest's `CHECK` is redefined by libtorch's `c10/util/logging_is_not_google_glog.h:121`. This is a plain `-Werror` preprocessor warning with no `-Wno-` switch for it.

waf stops at those two targets. A plain `wcb install` therefore left the prefix incomplete: no `share/`, `lib/cmake` or `lib/pkgconfig`, and some bins missing.

**What I did:**
- **Production prefix:** finished the install with `wcb -k install` (keep going). The prefix now has 21 bins, 21 libs, `share/wirecell` and `lib/cmake`. Nothing in the tag was changed.
- **clus doctests:** ran them from a separate, never-installed worktree `$Y/wct-0.38.0-dt` (same tag), configured with `CXXFLAGS += -Wno-error=range-loop-construct`.
- **pytorch doctest:** not built (not in the gate).

@porting_sbndbuild03: sbndbuild03 uses the same e26 compiler, so you should hit the same two failures.
